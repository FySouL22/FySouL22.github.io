أمن تطبيقات الويب ومعايير OWASP (Application Security)

دليل منهجي متكامل يغطي أشهر ثغرات تطبيقات الويب وفق معايير OWASP Top 10، بالإضافة إلى أمن واجهات برمجة التطبيقات OWASP API Security، منهجيات الفحص الثابت والديناميكي (SAST / DAST / SCA)، وحماية المتصفح وترويسات الأمان.

أمن الواجهات البرمجية APIs

معايير OWASP Top 10 - الثغرات الأخطر وطرق استغلالها وحمايتها

القائمة المعيارية المعتمدة عالمياً لأخطر المخاطر الأمنية في تطبيقات الويب الحديثة مع نماذج إثبات المفهوم (PoC) وطرق المعالجة البرمجية.

A01:2021 Critical

Broken Access Control & IDOR

فشل التطبيق في التحقق من صلاحيات المستخدم للوصول إلى مورد معين، مما يسمح للمهاجم بتعديل معرّف السجل (ID) في الطلب لعرض أو تعديل بيانات مستخدمين آخرين.

سيناريو الاستغلال (Attack Vector): GET /api/v1/invoices/download?invoice_id=9843 HTTP/1.1
الحل والوقاية: تطبيق نموذج تحكم وصول صارم (RBAC) والتحقق من ملكية الجلسة الحالية للسجل في استعلام قاعدة البيانات (مثل: WHERE id = ? AND user_id = current_user).
A02:2021 High

Cryptographic Failures

الإخفاقات التشفيرية، مثل تخزين البيانات الحساسة أو كلمات المرور بنصوص صريحة أو باستخدام خوارزميات ضعيفة/مكسورة مثل MD5 و SHA1، أو نقل البيانات دون تشفير TLS.

كود غير آمن (Bad Practice): password_hash = hashlib.md5(user_pass.encode()).hexdigest()
الحل والوقاية: استخدام خوارزميات مقاومة لمعالجات كروت الشاشة مثل Argon2id أو bcrypt مع Salt عشوائي، وإلزام تشفير TLS 1.3 لكافة الاتصالات.
A03:2021 Critical

Injection (SQLi, Command, SSTI)

دمج مدخلات المستخدم غير المنقحة مباشرة داخل استعلامات قواعد البيانات أو مفسرات الأوامر أو قوالب العرض، مما يتيح تغيير منطق التنفيذ أو تشغيل أوامر خبيثة على الخادم.

بايلودات تجريبية (Test Payloads): ' UNION SELECT null, username, password FROM users-- -
الحل والوقاية: استخدام الاستعلامات المجهزة مسبقاً (Prepared Statements / Parameterized Queries) واستخدام ORM موثوق وتجنب دوال Concatenation نهائياً.
A04:2021 High

Insecure Design & Business Logic

عيوب في التصميم المعماري ومنطق العمل البرمجي للتطبيق لا ترتبط بأخطاء كتابة الكود؛ مثل إمكانية شراء منتج بسعر سالب، أو إعادة تعيين كلمة المرور دون التحقق من الرمز القديم.

مثال منطق معيب: {"item_id": 42, "quantity": 1, "price": -50.00}
الحل والوقاية: نمذجة التهديدات (Threat Modeling) في مرحلة التخطيط المبدئي، والتحقق الصارم من أسعار ومنطق العمليات من جانب الخادم (Server-side Validation) فقط.
A05:2021 High

Security Misconfiguration

إهمال إعدادات الأمان الافتراضية؛ مثل ترك حسابات الإدارة الافتراضية نشطة، تمكين سرد المجلدات (Directory Listing)، أو عرض رسائل أخطاء تفصيلية (Stack Traces) تكشف بنية النظام.

أمثلة شائعة: Default Credentials: admin / admin | .git exposed on web root
الحل والوقاية: أتمتة عملية إعداد السيرفرات (Hardening)، حجب صفحات الخطأ المخصصة، إخفاء ملفات البيئة .env، وتطبيق سياسات الإعداد الآمن ككود (IaC).
A06:2021 High

Vulnerable & Outdated Components

استخدام مكتبات، أطر عمل، أو إضافات خارجية غير محدثة تحتوي على ثغرات أمنية معلنة (CVEs)، مثل ثغرات Log4j أو الإصدارات القديمة من jQuery و WordPress Plugins.

أداة الفحص السريع: npm audit || pip-audit || trivy fs .
الحل والوقاية: اعتماد أدوات Software Composition Analysis (SCA) مثل Dependabot أو Snyk، وتحديث الحزم الأمنية بصورة دورية ومجدولة.
A07:2021 High

Identification & Authentication Failures

ضعف آليات التحقق من الهوية؛ كالسماح بهجمات التخمين الآلية (Brute Force / Credential Stuffing)، غياب التحقق بخطوتين (MFA)، أو عدم إلغاء صلاحية الجلسة القديمة بعد تسجيل الخروج.

سيناريو الهجوم: No Rate Limiting on /api/login allows 10,000 requests/min
الحل والوقاية: فرض Rate Limiting، قفل الحساب مؤقتاً بعد محاولات فاشلة، فرض المصادقة الثنائية (2FA/TOTP)، وتجديد معرف الجلسة فور تسجيل الدخول الناجح.
A08:2021 High

Software & Data Integrity Failures

الثقة العمياء في التحديثات أو الأكواد أو الحزم دون التحقق من توقيعها الرقمي، بالإضافة إلى ثغرات فك التسلسل غير الآمن (Insecure Deserialization) التي تقود إلى تنفيذ أوامر RCE.

كود غير آمن في بايثون: import pickle; data = pickle.loads(untrusted_user_input)
الحل والوقاية: استخدام صيغ تبادل بيانات نصية نقية ومحدودة مثل JSON، وتوقيع ملفات التحديث والمكتبات برمجياً قبل تشغيلها.
A09:2021 Medium

Security Logging & Monitoring Failures

عدم تسجيل الأحداث الأمنية الهامة (مثل فشل تسجيل الدخول أو محاولات كسر الصلاحيات)، أو عدم مراقبة السجلات مركزياً مما يسمح للمخترقين بالبقاء داخل الشبكة لشهور دون اكتشاف.

المشكلة: Attacker scans admin panel for 30 days without any alerts triggered
الحل والوقاية: تجميع السجلات في نظام مركزي (SIEM مثل Wazuh أو Splunk)، وضبط تنبيهات فورية للمسؤول عند تجاوز عتبة محددة من الأخطاء الأمنية.
A10:2021 Critical

Server-Side Request Forgery (SSRF)

قدرة المهاجم على إجبار الخادم المستهدف على إرسال طلبات HTTP إلى خدمات داخلية خاصة أو إلى واجهات الـ Cloud Metadata لسحب مفاتيح الحسابات السحابية الحساسة.

بايلود استهداف سحابة AWS / GCP: http://169.254.169.254/latest/meta-data/iam/security-credentials/
الحل والوقاية: وضع قائمة بيضاء (Whitelisting) للنطاقات والبروتوكولات المسموح للخادم بالتواصل معها، وحجب العناوين المحلية (127.0.0.1, 10.0.0.0/8, 169.254.169.254).

أمن الواجهات البرمجية (OWASP API Security Top 10)

معظم تطبيقات الويب الحديثة وتطبيقات الموبايل تعتمد على RESTful و GraphQL APIs، وتواجه تهديدات موجهة خاصة بها:

API1:2023 Critical

Broken Object Level Authorization (BOLA)

استبدال الـ ID في مسار الـ API للحصول على كائن مستخدم آخر. تُعتبر الثغرة الأكثر انتشاراً وخطورة في واجهات الـ API المعاصرة.

الطلب: GET /api/v2/messages/user_9921 HTTP/1.1
العلاج: فحص سياسات التخويل على مستوى الكائن في كل نقطة وصول (Endpoint) والتأكد أن العميل يمتلك المورد بالفعل.
API3:2023 High

Broken Object Property Level (Mass Assignment)

إرسال حقول إضافية غير مرئية في واجهة المستخدم داخل جسم الـ JSON (مثل "role": "admin" أو "is_verified": true) ليقوم الخادم بحفظها تلقائياً.

الحقن في ملف JSON: {"name": "Mohamed", "email": "m@test.com", "is_admin": true}
العلاج: تحديد الحقول المسموح بتعديلها صراحة (DTO / Schema Whitelisting) وتجاهل أي حقل إضافي غير مصرح.
API4:2023 Medium

Unrestricted Resource Consumption

غياب حدود استهلاك الموارد وحجم الطلبات، مما يتيح إرسال طلبات ضخمة (مثل طلب 10,000 مستخدم في صفحة واحدة ?limit=100000) لإسقاط قاعدة البيانات.

الطلب المنهك: GET /api/transactions?page=1&size=99999999 HTTP/1.1
العلاج: فرض حد أقصى للصفحة (Max Pagination Limit: 50)، وتقييد حجم ملفات الـ Upload، وضبط Rate Limiter على الـ Gateway.

منهجيات وأدوات فحص أمن التطبيقات (AppSec Toolkit)

الممارسات المتبعة لدمج الأمن في دورة حياة تطوير البرمجيات (Secure SDLC & DevSecOps):

SAST Whitebox

Static Application Security Testing

فحص الكود المصدري (Source Code) ثابتاً دون الحاجة لتشغيل التطبيق، لاكتشاف الثغرات والمفاتيح المشفرة والممارسات البرمجية السيئة مبكراً.

أشهر الأدوات: Semgrep, SonarQube, Bandit (Python), Checkmarx
الميزة: تكتشف موضع الثغرة ورقم السطر بالضبط في الكود البرمجي قبل طرحه في بيئة الإنتاج.
DAST Blackbox

Dynamic Application Security Testing

فحص التطبيق وهو يعمل في بيئة الاختبار بمحاكاة سلوك المهاجم الخارجي وإرسال طلبات وحمولات خبيثة لتحليل ردود الفعل ورموز الحالة.

أشهر الأدوات: OWASP ZAP, Burp Suite Professional, Nuclei, Arachni
الميزة: تؤكد إمكانية استغلال الثغرة في بيئة التشغيل الفعلية وتكشف أخطاء تكوين السيرفرات والشبكة.
Threat Modeling Architecture

نمذجة التهديدات وفق إطار STRIDE

تحليل معماري منظم لتحديد المخاطر المحتملة قبل كتابة سطر كود واحد؛ مقسمة إلى: انتحال الهوية (Spoofing)، التلاعب (Tampering)، التنصل (Repudiation)، تسريب البيانات (Information Disclosure)، الحرمان من الخدمة (DoS)، وتصعيد الصلاحيات (Elevation of Privilege).

أدوات مساعدة: OWASP Threat Dragon, Microsoft Threat Modeling Tool
الميزة: توفر 80% من تكاليف ترقيع الثغرات إذا تم تدارك عيوب التصميم من البداية.

ترويسات الأمان وحماية الواجهة الأمامية (Security Headers)

قائمة الرؤوس الأساسية التي يجب أن يرد بها الخادم على متصفحات المستخدمين لصد هجمات Clickjacking, XSS, و MiTM:

CSP Anti-XSS

Content Security Policy (CSP)

أقوى رأس أمني يخبر المتصفح بالمصادر الموثوقة لتحميل السكربتات والصور، ويمنع تنفيذ أي سكربت خبيث يتم حقنه عبر ثغرات XSS.

قيمة الترويسة الموصى بها: Content-Security-Policy: default-src 'self'; script-src 'self' https://trusted.cdn.com; object-src 'none';
ملاحظة: تجنب استخدام 'unsafe-inline' أو 'unsafe-eval' للحفاظ على فاعلية الحماية.
Cookies Anti-Session Hijack

Secure Cookie Flags

حماية كوكيز جلسة المستخدم من السرقة والتلاعب عبر متصفح الضحية:

ترويسة الكوكيز الآمنة: Set-Cookie: session_id=xyz789; Secure; HttpOnly; SameSite=Strict; Path=/
Flags: HttpOnly تمنع JavaScript من قراءة الكوكي، Secure تمنع إرساله عبر HTTP العادي، SameSite=Strict تحمي من ثغرات CSRF.
Headers Hardening

HSTS & Clickjacking Defense

إجبار المتصفح على تشفير الاتصال دائماً، ومنع تحميل الموقع داخل إطارات iframes خفية:

الترويسات الإلزامية: Strict-Transport-Security: max-age=31536000; includeSubDomains
X-Frame-Options: DENY
X-Content-Type-Options: nosniff
الفائدة: إغلاق هجمات التجسس على الشبكات المفتوحة ومنع سرقة نقرات المستخدمين.
